# 3D Express ← أسلوب Unity: الخطة المرحلية ومراجعة الأقسام

> طلب المالك (2026-10-30): «أريد تطوير برنامج 3D Express بحيث يكون مشابهاً جداً لبرنامج Unity 3D»، و«مرّر كل شيء على أقسام الشركة».
> المصدر: `aboanas990-dev/3d-express` → `3d-express-studio5.html` (4538 سطراً، three.js 0.160 + GSAP). فرع العمل: `claude/project-thread-om9nmr`.

## المعنى المعتمد للطلب
نفس **طريقة عمل محرر Unity وتخطيطه** (Hierarchy · Scene/Game · Inspector · Project/Console · أدوات Q W E R · زر Play/Pause/Step · وضع اللعب الذي يُرجع المشهد عند الإيقاف · مكوّنات تُضاف للكائن)، **بهوية شركتنا وكودنا نحن**. لا شعارات Unity ولا اسمها ولا أصولها داخل البرنامج (قسم القانون).

## ما الموجود اليوم (studio5)
شريط علوي + Ribbon على طريقة Autodesk، مكتبة يسار، نافذة عرض، مستكشف + خصائص يمين، خط زمني GSAP، أدوات تحريك/تدوير/تحجيم (Q W E R موجودة)، شخصيات بهيكل عظمي، رسم 2D وبثق، توليد AI، تصيير وتصدير، ترخيص Express Licence.

## المراحل

| # | المرحلة | ماذا يرى المستخدم | الجهد |
|---|---|---|---|
| 1 | **تخطيط المحرر + وضع اللعب** | تخطيط Unity: Hierarchy يسار، Scene/Game في الوسط، Inspector يمين، لوحة سفلية بتبويبات Project · Console · Animation، شريط أدوات بأزرار ▶ ⏸ ⏭ في المنتصف. وضع اللعب يأخذ لقطة للمشهد ويعيدها عند الإيقاف (مثل Unity) مع تلوين المحرر أثناء اللعب. كائن «كاميرا رئيسية» وعرض Game منها. زر للعودة للتخطيط الكلاسيكي (لا تُحذف أي ميزة). | كبير |
| 2 | **المكوّنات (Components)** | زر «إضافة مكوّن» في Inspector: جسم فيزيائي (جاذبية وكتلة)، مُصادِم صندوق/كرة، دوران تلقائي، تحكم بالكيبورد WASD، تتبّع الكاميرا. كل مكوّن بطاقة قابلة للطي مع مربع تفعيل. | كبير |
| 3 | **السكربتات والقوالب (Prefabs)** | سكربت JavaScript لكل كائن (Start / Update) بمحرر كود، قوالب كائنات قابلة لإعادة الاستخدام، مجلدات أصول في Project محفوظة في IndexedDB. | كبير |
| 4 | **البناء والتشغيل (Build)** | «بناء» يخرج لعبة/تجربة تفاعلية كملف HTML مستقل يعمل بلا البرنامج. | متوسط |
| 5 | **التلميع والإطلاق** | الجوال واللمس، الدليل ثنائي اللغة، صفحة المتجر، رقم إصدار جديد. | متوسط |

كل مرحلة = طلب دمج (PR) مستقل يراجعه المالك قبل الدمج. المرحلة التالية لا تبدأ إلا بعد موافقته على السابقة.

## مسار الرندرينق (طلب المالك 2026-10-30: «تحسين الريندرينق بشكل كبير يشابه تلك البرامج القوية»)

| # | المرحلة | الحالة |
|---|---|---|
| R1 | سلسلة مؤثرات فورية (AO، Bloom، تنعيم، تدرّج ألوان، ACES/AgX) بأربعة مستويات جودة، في المشهد واللعبة والفيديو والصورة | منفّذة في PR #10 |
| R2 | سماء واقعية بشمس تضيء المشهد وبيئة انعكاسات منها | منفّذة في PR #10 |
| R3 | رندر نهائي بتتبّع المسار (three-gpu-pathtracer) مع عيّنات وارتدادات وإيقاف وحفظ | منفّذة في PR #10 |
| R4 | لاحقاً: خرائط HDRI يرفعها المستخدم، عمق الميدان (DOF) بكاميرا فيزيائية، ضوء مساحي (Area light)، إزالة التشويش، رندر فيديو بتتبّع المسار | مقترحة |

مراجعة الأقسام لمسار الرندرينق: الأداء: المؤثرات تنخفض تلقائياً على الأجهزة الضعيفة، ومحرك تتبّع المسار لا يُحمَّل إلا عند استخدامه. الأمن: مكتبتان جديدتان من jsdelivr بإصدار مثبّت (three-mesh-bvh 0.7.8، three-gpu-pathtracer 0.0.23، رخصة MIT) وتُضافان إلى THIRD_PARTY_NOTICES. الهوية: ألوان الواجهة لم تتغير. القانون: رخص MIT تسمح بالاستخدام التجاري مع ذكرها.
